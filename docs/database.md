# پایگاه داده

اسکیما با مهاجرت‌های لاراول ساخته می‌شود. نمودار جدول‌ها در [erd.md](erd.md) است. این صفحه می‌گوید داده کجا ذخیره می‌شود، این نسخه چه تغییری در دیتابیس دارد، و دیتابیسِ از قبل ساخته‌شده چطور به‌روز می‌شود.

## پنل مشتریان

مهاجرت `2026_09_25_160000_create_portal_tables` این جدول‌ها را می‌سازد: `customers`، `products`، `customer_orders`، `customer_order_items`، `customer_threads`، `customer_thread_messages`. قابلیت `portal` را هم روشن می‌کند. مهاجرت `2026_09_25_160100_create_customer_ticket_tables` جدول‌های `customer_tickets` و `customer_ticket_messages` را اضافه می‌کند. شمارهٔ تیکت مثل `TKT-0001` است. میزها `sales`، `support` و `management` هستند. وضعیت تیکت: `open`، `in_progress`، `answered`، `closed`. اولویت: `low`، `normal`، `high`.

اگر دیتابیس را قبلاً ساخته‌اید و نمی‌خواهید داده پاک شود:

```bash
cd backend
php artisan migrate
php artisan db:seed --class=Database\\Seeders\\DemoPortalSeeder
```

سیدر فقط وقتی مشتری نمونه نباشد محصول، دو حساب، یک سفارش، دو گفتگو و دو تیکت نمونه می‌سازد. حساب تأییدشده `customer@ideban.test` و حساب در انتظار `pending@ideban.test` است. رمز هر دو `123456` است. دیتابیس موجود را با `portal-upgrade.sql` به‌روز کنید، نه با ایمپورت دوبارهٔ دامپ کامل.

## گزارش کار و تقویم

گزارش کار، ارسال وظیفه و تقویم شمسی ستون یا جدول جدیدی لازم ندارند.

| قابلیت | ذخیره |
| --- | --- |
| تقویم شمسی یا میلادی | `companies.settings.calendar` با مقدار `jalali` یا `gregorian`. اگر خالی باشد برنامه `jalali` نشان می‌دهد. |
| منطقهٔ زمانی | ستون `companies.timezone`. پیش‌فرض شرکت نمونه `Asia/Tehran`. |
| ساعت کاری | `work_schedules`. هفتهٔ ایران: شنبه تا پنجشنبه کاری، جمعه تعطیل. شروع ۰۹:۰۰، پایان ۱۷:۰۰، استراحت ۶۰ دقیقه، ارفاق ۱۵ دقیقه. |
| گزارش کار شخص | خواندن `attendance_days`، `attendance_events` و `daily_reports`. نوشتن تازه فقط وقتی مدیر ساعت را اصلاح کند یا خود شخص ورود و گزارش ثبت کند. |
| وظیفهٔ فرستاده‌شده | همان جدول `tasks`. `assignee_id` گیرنده است و `reporter_id` مدیر فرستنده. |

تاریخ در پایگاه داده میلادی است و زمان‌ها UTC. شمسی فقط هنگام نمایش، با منطقهٔ زمانی شرکت، ساخته می‌شود. این قانون عوض نشده است.

## دیتابیس را قبلاً ساخته‌اید

مهاجرت نزنید و فایل SQL را دوباره ایمپورت نکنید، مگر اینکه بخواهید دادهٔ فعلی پاک شود.

اگر فقط قابلیت‌های جدید را می‌خواهید، هیچ دستوری لازم نیست. تقویم پیش‌فرض شمسی است و گزارش کار همان ردیف‌های حضور موجود را نشان می‌دهد.

اگر شرکت نمونه است و می‌خواهید گزارش کار چند هفته داده داشته باشد، بعد از گرفتن آخرین کد:

```bash
cd backend
php artisan db:seed --class=Database\\Seeders\\DemoWorkHistorySeeder
```

این سیدر:

- اگر `settings.calendar` خالی باشد آن را `jalali` می‌گذارد و انتخاب قبلی میلادی را عوض نمی‌کند.
- اگر برای شرکت نمونه روز کاریِ گذشته وجود داشته باشد، حضور را دوباره نمی‌سازد.
- اگر وظیفهٔ «جمع‌بندی گزارش کار هفته» وجود داشته باشد، وظیفهٔ تکراری نمی‌سازد.
- روی شرکت دیگری غیر از `ideban-almas` اثری ندارد.

رمز حساب‌ها را عوض نمی‌کند.

## نصب تازه

یکی از این دو راه را روی دیتابیس خالی اجرا کنید، نه هر دو را.

- `php artisan migrate --seed`
- یا ایمپورت `virtual-company-os-mysql.sql` (MySQL / MariaDB / phpMyAdmin)
- یا سه فایل `backend/database/sql/postgresql/` به ترتیب

جزئیات نصب در [install.md](install.md) است. رمز همهٔ حساب‌های نمونه `123456` است.

بعد از seed یا ایمپورت، شرکت نمونه این‌ها را دارد:

- تقویم شمسی و منطقهٔ زمانی تهران
- حضور امروز برای چند نفر
- حدود سه هفته روز کاریِ بسته‌شده برای هشت نفر، با تأخیر، استراحت، یک مرخصی، یک مأموریت، یک غیبت و یک اصلاح ساعت توسط مدیر
- گزارش صبح و گزارش روزانه برای چند نفر در روزهای اخیر
- وظیفه‌هایی که مدیرعامل برای افراد فرستاده، شامل یک وظیفهٔ انجام‌شده و یک وظیفهٔ عقب‌افتاده

فایل سوم PostgreSQL فقط ساعت امروز را، اگر نباشد، اضافه می‌کند. تاریخچهٔ گزارش کار داخل `02_seed.sql` است.

## ساخت دوبارهٔ فایل SQL

فقط وقتی سیدر عوض شده و می‌خواهید فایل ایمپورت با آن یکی باشد:

```bash
cd backend
php artisan migrate:fresh --seed
python3 database/sql/export-mysql.py
php database/sql/export-postgresql.php
```

`migrate:fresh` دیتابیس همین محیط را پاک می‌کند. روی دیتابیس مشترکی که دادهٔ واقعی دارد نزنید.
