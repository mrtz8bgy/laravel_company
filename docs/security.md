# امنیت فاز ۱

اعمال‌شده:

- رمز hash شده، سیاست حداقل ۸ نویسه با حرف بزرگ، عدد و نماد
- مجوز روی middleware بک‌اند، نه فقط UI
- scope شرکت fail-closed
- توکن به شرکت متصل است و با خروج حذف می‌شود
- Sanctum به session وب fallback ندارد
- دعوت با sha256 ذخیره می‌شود؛ لینک فقط یک‌بار در پاسخ ایجاد برمی‌گردد
- activity log برای ایجاد، ویرایش، حذف، ورود، خروج و تخصیص
- فیلدهای رمز و توکن در لاگ redact می‌شوند
- rate limit ورود و onboarding
- هدرهای `nosniff`، `X-Frame-Options`، `Referrer-Policy`
- اعتبارسنجی Form Request
- آخرین مالک قابل حذف نیست
- آپلود فایل در این فاز وجود ندارد. تا وقتی MIME، اندازه، دیسک خصوصی و دانلود مجاز پیاده نشود، endpoint آپلود ساخته نمی‌شود.
- ثبت حضور فقط برای خود کاربر است. اصلاح رکورد دیگران مجوز `attendance.correct` می‌خواهد و در activity log می‌ماند.
- IP ثبت حضور ذخیره می‌شود و در پاسخ تابلو برنمی‌گردد.
- اگر feature حضور خاموش باشد، مسیرهای حضور ۴۰۳ می‌دهند.

عمداً هنوز نیست و نباید «تمام‌شده» فرض شود:

- 2FA فقط ستون و معماری است، نه جریان TOTP
- توکن SPA در `localStorage` است. برای موبایل Bearer درست است؛ برای مرورگر، HttpOnly cookie در سخت‌سازی فاز ۱۴ بهتر است
- اسکن ویروس فایل هنوز معماری است، چون آپلودی وجود ندارد
- Rate limit پشت Nginx باید `TRUSTED_PROXIES` درست داشته باشد وگرنه همهٔ کاربران یک IP دیده می‌شوند
- Row Level Security در PostgreSQL هنوز فعال نیست. لایهٔ اپلیکیشن ایزوله را اعمال می‌کند؛ RLS دفاع اضافهٔ فاز ۱۴ است

حقوق و کد ملی در `hr_profiles` هستند. `/hr/me` آن‌ها را برنمی‌گرداند. دیدن و نوشتن‌شان مجوز `hr.salary.view` می‌خواهد و نقش مالی این مجوز را ندارد. activity log این فیلدها و تماس اضطراری را redact می‌کند. پروژهٔ خصوصی برای غیرعضو ۴۰۴ است. تأیید درخواست خود ممنوع است.
